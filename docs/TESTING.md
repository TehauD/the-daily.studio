In sandboxes: `CHROMIUM_PATH=/path/to/chromium NO_SANDBOX=1 npm run test:e2e`. To run a few suites, name them: `node test/run.cjs clips midi` (any file whose name contains one of the words). `JOBS=3` sets how many run at once (default: half the processors, 1 to 4). `BASE_URL=https://…` tests a deployed site instead of the local server.

The suites that time drawing (`e2e-concert`, `e2e-show`) run on their own after the others, so the frames they measure are not slowed by other browsers. A file that fails while others run beside it is run once more on its own: if it passes then, the run names it as **flaky (failed beside other tests, passed alone)** and does not fail; a real fault fails both times. `STRICT=1` makes a flaky file count as a failure. Checks that wait for the app (a start route opening, a section scrolling into view) poll until the condition holds rather than sleeping a fixed time, so a slow machine gets longer and a fast one does not wait.

## The browser suites

**Which build is tested (2.40).** The suites serve `dist/`, the hosted site's build with its rooms and font files: `test/run.cjs` builds it first, and `test/lib.cjs` rebuilds it when it is older than `index.html`. `STANDALONE=1` serves the single-file `index.html` instead, and CI runs MIDI, Shower mode, song links and Simple that way too.

Each file starts its **own** static server, its own Chromium (fake microphone and camera) and fresh browser contexts through `test/lib.cjs`, so nothing one file leaves behind (settings, songs, a stuck service worker) can change another, and they run side by side. Every file ends by asserting that the page produced no console errors, page errors or failed requests.

## Other browsers' engines (2.19.1)

`test/xbrowser.cjs` is a short pass in Safari's engine (WebKit) and Firefox's, over what people rely on most: the studio opens, the audio engine and its worklets start, the song plays, the visuals draw, wide and vertical videos record at their sizes, Your video plays behind, the tip jar draws its code, Settings and Help open and the problem report is made. Run it with `BROWSER=webkit node test/xbrowser.cjs` or `BROWSER=firefox node test/xbrowser.cjs` (after `npx playwright install --with-deps webkit firefox`); with no `BROWSER` it runs in Chromium. Where an engine lacks something the browser provides (recording a canvas, say), the check says so by name instead of passing quietly. CI runs it for WebKit and Firefox in the `browsers` job, which reports without blocking until it has been green on hosted runners; the main `e2e` job (Chromium, every suite) blocks a merge when it fails.

## Hum to Song checks

The e2e suite runs a synthetic hummed melody (16 notes, 25 cents sharp) through the real analysis and arranger and asserts every note, the tempo, key, section list, valid chords, lead-guitar notes in verse, chorus and bridge, style and key re-arrangement, the Ctrl + . stop, and the center-stage defaults. It also drives the **guitar coach** with stand-in guitar readings (tune six strings, play four chords, reach play-along), the **adaptive studio** (four plain tabs for a new visitor, more after use, the Tools override) and the **full-screen center stage** (fills the screen; Studio button returns). axe-core (WCAG A/AA) was run on the first screen, the start panel and the coach in light and dark with no violations. Real voices are noisier: also try humming, singing with words, and a voice memo on the deployed site.

## Manual checks before a release

Automated tests use a fake microphone and camera and do not reach the third-party camera hosts. The full list, in the order to do it with real gear (about 45 minutes), is **[HARDWARE_CHECKLIST.md](HARDWARE_CHECKLIST.md)**. The short version, on the deployed site:

1. **Real audio:** connect a real interface or headphone mic, play, then press Ctrl/Cmd + . and confirm the browser's recording indicator turns off. Resume; confirm the microphone stays off until Connect.
2. **Monitoring:** off by default; tick "Hear myself" with headphones and confirm sound; untick.
3. **Camera:** Visuals ▸ camera backdrop, look = *person* and *edges*; hand tracking. Confirm models load (Network tab shows jsDelivr and storage.googleapis.com).
4. **Offline:** load once, go offline, reload; install to home screen on a phone.
5. **Browsers:** current Chrome/Edge, Safari (macOS and iOS), Firefox. Web Audio and camera behave differently; note any gaps in the changelog. On an iPhone, check **Keep songs safe** before and after Add to Home Screen.
6. **Accessibility:** keyboard-only pass through start card, Audio panel and Appearance; run axe on the light and dark default palettes and the Audio dialog.
7. **Journal:** `/journal/` loads, imports an export, and the studio's Reset does not remove it.

## What is not covered

Very long sessions, large stem imports on low-memory phones, screen-reader pass of every panel, and non-Chromium audio latency. How the band and a tuned voice *sound* on real speakers and headphones is measured by numbers here, not judged by ears: that is section 15 of [HARDWARE_CHECKLIST.md](HARDWARE_CHECKLIST.md). The full list of known gaps, with what each release closed, is [GAPS.md](GAPS.md).

## Timing checks under load

The full run starts many browsers at once, so a page can be starved for tens of milliseconds. Checks that time things must not depend on when the test happens to look:

- Count events from the app's own record of them (the show's `LX.lastStrobe` and `LX.lastStrobeBar`), not by sampling a value that fades within a few frames.
- Wait for the condition itself (the recorder has handed over data; `t.poll`), not for a fixed number of seconds.
- If a timing check fails only under load, look at how the test measures before widening a tolerance. `e2e-latency` recorded through a ScriptProcessor, which runs on the page's thread and drops audio when that thread is starved: the re-amp gap came out 3 ms short in full runs. Since 2.31 the timing tests record with an AudioWorklet on the audio thread, which cannot drop; the check still asks for ± 1 ms and passes with four other files running beside it. (2.25.1 made late-scheduled takes skip in against the audio clock; that was a real improvement, but not this failure's cause.)
